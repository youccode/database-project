## 2. 프로젝트 주제 및 비즈니스 모델

논문과 논문 사이의 인용 관계를 탐색해 선행 연구를 찾고, 찾은 논문을 연구팀의 공동 프로젝트에 모아 함께 관리하는 웹 서비스다. 프로젝트 구성원들은 논문 목록을 공유하고 검토 상태, 태그, 메모를 함께 관리한다.

비즈니스 모델은 프리미엄 구독형을 검토한다. 논문 검색, 직접 인용·피인용 목록 조회, 공동 프로젝트의 기본 관리는 기본 기능으로 제공하고, 여러 단계의 인용 관계를 그래프로 시각화하고 상세 필터로 탐색하는 기능은 유료 구독 기능으로 제공하는 안이다. 이는 초기 수익 모델 가설이며, 실제 요금과 구독·결제 처리는 이번 학기 구현 범위에 포함하지 않는다.

구독형의 향후 확장 기능으로, 연구자가 아직 공개하지 않은 원고를 초안으로 만들고 DB에 등록된 논문을 그 원고의 참고문헌 후보로 연결해 작성 중인 원고가 인용할 논문 목록과 선행 연구 관계를 시뮬레이션하는 기능을 검토한다. 선택한 논문의 서지정보를 BibTeX로 내보내면 수기 입력과 서식 오류를 줄이고 필수 정보 누락을 확인할 수 있다. 이 기능은 공개 논문의 실제 인용 관계와 별도로 관리하며, 이번 학기 구현 범위에는 포함하지 않는다. 원본 서지정보의 정확성까지 자동 보증하는 기능으로 설명하지 않는다.

## 3. 해결하고자 하는 문제

- 특정 논문이 참고한 선행 연구와 해당 논문을 인용한 후속 연구를 연속적으로 찾기 번거롭다.
- 공동 연구자들이 참고 논문과 검토 내용을 각자 다른 곳에 정리해 자료가 흩어지거나 중복될 수 있다.
- 같은 연구가 arXiv 업데이트와 학회·저널본으로 나뉘어 공개되면 어떤 판본을 볼지 구분하기 어렵다.
- 탐색한 선행 논문을 자신의 미공개 원고의 참고문헌 후보로 정리하고, 서지 형식으로 옮기는 과정에서 누락이나 서식 오류가 생길 수 있다.

## 4. 주요 사용자

- 논문을 공동 작성하거나 선행 연구를 함께 조사하는 대학원생 및 연구자 팀
- 특정 연구 주제의 선행·후속 논문을 찾는 학부생과 연구자
- 지도교수 및 공동연구자와 문헌 목록을 공유하려는 연구팀

## 5. 핵심 기능

![예상 Application 화면 시안 — 실제 구현 전 목업](./images/application-demo.png)

- 논문이 인용한 논문과 해당 논문을 인용한 논문을 탐색한다.
- arXiv의 특정 버전, 학회본, 저널본을 각각 별도 논문 기록으로 관리하고, 같은 연구의 관련 판본을 연결한다.
- 인용 관계는 논문 기록 사이의 연결로 관리하며, 본문에서 인용이 등장한 문장이나 위치는 저장하지 않는다.
- 탐색 화면에서 학회·저널본만 보기, 최신 arXiv본 보기, 전체 판본 보기를 선택한다.
- 연구 프로젝트를 만들고 구성원을 추가해 공동 논문 목록을 공유한다.
- 프로젝트 안에서 논문 검토 상태, 태그, 메모를 함께 관리한다.
- 제목, 저자, 출판처, 연도, DOI·arXiv ID로 논문을 검색하고 필터링한다.

## 6. 예상 테이블 구성 및 데이터 구조

아래 14개 테이블을 핵심 후보로 설계한다. 논문과 저자·출판처·인용 관계를 나누어 저장하고, 프로젝트·사용자 및 논문·태그 사이의 다대다 관계는 연결 테이블로 표현한다.

**데이터 범위:** 전체 학술 논문 데이터를 포괄적으로 수집·구축하는 것은 본 학기 프로젝트의 범위를 넘어서는 작업이다. 따라서 연구자의 전공 분야와 연계된 컴퓨터과학 논문을 중심으로 범위를 정하고, 인용 관계 탐색과 공동 문헌 조사라는 핵심 기능을 검증할 수 있는 시제품 데이터 구성을 목표로 한다. 세부 분야와 논문 선정 기준은 데이터 확보 가능성과 구현 범위를 검토해 구체화한다.

논문 메타데이터와 참고문헌·피인용 관계는 공개 학술 검색 서비스, 학술 출판처 또는 학술 데이터 제공기관의 정보를 활용하는 방안을 검토한다. 실제 데이터 출처와 수집 방식은 접근 가능성, 활용 조건, 데이터 품질을 확인한 뒤 정하며, 수집된 정보의 누락 가능성도 고려해 시제품의 데이터 범위를 설명한다.

| 테이블 | 한 행의 의미 | 주요 키 및 관계 후보 |
| --- | --- | --- |
| `users` | 서비스를 사용하는 연구자 한 명 | PK `user_id`; 이메일 UNIQUE 후보 |
| `research_projects` | 연구팀의 문헌 조사 프로젝트 하나 | PK `project_id`; FK `created_by_user_id` → `users` |
| `project_members` | 한 사용자가 한 프로젝트에 참여하는 관계 하나 및 역할 | 복합 PK (`project_id`, `user_id`); FK `project_id` → `research_projects.project_id`, FK `user_id` → `users.user_id` |
| `project_papers` | 프로젝트가 논문 기록 하나를 공동 문헌 항목으로 포함한 관계 하나 | 복합 PK (`project_id`, `paper_id`); FK로 프로젝트와 논문 참조; 추가자 `added_by_user_id`는 `users.user_id`를 참조하는 FK 후보 |
| `papers` | 인용·검색 대상이 되는 공개 판본 또는 출판 기록 하나. 예: arXiv 특정 버전, 학회본, 저널본 | PK `paper_id`; 판본·제목·공개일 등; 같은 연구의 관련 판본은 `paper_relations`로 연결; `venue_id`는 `venues.venue_id`를 참조하며 미출판 프리프린트에서는 NULL 허용 후보 |
| `paper_identifiers` | 논문 기록을 외부에서 찾는 식별자 하나. 예: DOI 또는 arXiv ID | PK `identifier_id`; FK `paper_id` → `papers.paper_id`; 식별자 종류와 값의 UNIQUE 범위는 판본 식별 정책과 함께 확정 |
| `paper_relations` | 같은 연구의 두 논문 기록 사이의 업데이트·출판 판본 관계 하나 | PK `relation_id`; FK `from_paper_id` → `papers.paper_id`와 FK `to_paper_id` → `papers.paper_id`; 업데이트·출판 관계 유형 후보 |
| `authors` | 저자 한 명 | PK `author_id`; ORCID UNIQUE 후보 |
| `paper_authors` | 한 저자가 한 논문 기록에 참여한 관계 하나 및 저자 순서 | 복합 PK (`paper_id`, `author_id`); FK `paper_id` → `papers.paper_id`, FK `author_id` → `authors.author_id` |
| `venues` | 논문이 발표되거나 실린 학회 또는 학술지 하나. 예: ICML, IEEE S&P 또는 학술지 | PK `venue_id`; 출판사 자체가 아니라 발표·출판 매체를 의미; arXiv 저장소는 이 테이블의 venue에 포함하지 않는 설계 후보 |
| `citations` | 특정 논문 기록 A가 특정 논문 기록 B를 인용하는 관계 하나. 본문 내 인용 문장·위치는 저장하지 않음 | PK `citation_id`; FK `citing_paper_id` → `papers.paper_id`, FK `cited_paper_id` → `papers.paper_id`; 같은 논문 기록 쌍 중복 방지를 위한 두 컬럼의 UNIQUE 후보 |
| `project_tags` | 한 프로젝트에서 사용하는 태그 하나 | PK `tag_id`; FK `project_id` → `research_projects` |
| `project_paper_tags` | 프로젝트의 논문 항목에 태그를 연결한 관계 하나 | 복합 PK (`project_id`, `paper_id`, `tag_id`); 프로젝트 논문 및 태그 참조 |
| `paper_notes` | 프로젝트 논문 항목에 구성원이 작성한 메모 하나 | PK `note_id`; FK로 프로젝트 논문, 작성 사용자 참조 |

`project_members`는 사용자와 프로젝트의 다대다 관계 및 구성원 역할을 나타낸다. `project_papers`는 프로젝트와 논문의 다대다 관계를 나타낸다. `citations`는 `papers`를 `citing_paper_id`와 `cited_paper_id` 두 역할로 참조하며, `citation_id`는 인용 관계 행 자체를 식별한다. `paper_relations`는 같은 연구에 속한 판본 간 관계를 저장하며 실제 참고문헌 인용 관계와 구분한다.

현재 설계에서는 arXiv의 각 버전과 학회·저널본을 별도 `papers` 행으로 저장하고, 인용 관계도 이 개별 논문 기록 사이에 저장한다. `paper_id`는 서비스 내부 식별자이고 DOI·arXiv ID는 외부 식별자다. ORCID는 논문이 아니라 저자를 식별하므로 `authors`에 둔다.

## 7. 향후 구현 계획

프로젝트는 서비스 요구사항 구체화, 데이터베이스 설계 확정, 애플리케이션 구현·검증의 순서로 진행한다. 각 단계의 결과와 피드백을 다음 단계에 반영하며, 세부 기능과 데이터 범위는 설계 및 구현 과정에서 구체화한다.

### 2차 고도화: 요구사항·화면·ERD 초안 구체화

- **사용자와 기능 흐름:** 논문 검색과 상세 정보 확인, 참고문헌·피인용 논문 탐색, 논문을 공동 프로젝트에 추가하는 흐름을 정의한다. 프로젝트 생성·구성원 초대와 검토 상태·태그·메모 관리 흐름도 구체화한다.
- **주요 화면:** 논문 검색 결과, 논문 상세 및 판본·인용 관계 보기, 프로젝트의 공동 논문 목록, 프로젝트 구성원·태그·메모 관리 화면을 구성한다. 각 화면에서 사용자가 입력·조회·수정하는 정보를 정리한다.
- **ERD 초안:** 구체화한 기능 흐름을 반영해 테이블과 관계 초안을 작성한다. 1차 기획 이후 바뀐 요구사항이나 테이블이 있다면 변경 내용과 이유를 함께 기록한다.
- **데이터 범위:** 사용할 논문 분야와 선정 기준, 데이터 수집 가능성 및 데이터의 한계를 정리한다.

### 3차 데이터베이스 분석·설계: 최종 ERD와 SQL 설계

- 2차 ERD 초안을 검토해 엔터티·관계·한 행의 의미를 확정하고 **최종 ERD**를 작성한다.
- 테이블 명세서에 컬럼명, 데이터 타입, PK/FK, NULL 허용 여부와 UNIQUE·CHECK 등 무결성 제약조건을 정리하고, 정규화 및 설계 근거를 설명한다.
- 최종 설계에 맞춘 DDL과 시연용 데이터를 준비한다. 논문 검색, 참고문헌·피인용 논문 조회, 판본 관계 및 프로젝트별 논문 집계를 위한 JOIN·집계·서브쿼리 SQL을 작성하고 결과를 확인한다.
- 자주 검색·연결하는 컬럼의 인덱스 적용 이유와 프로젝트 구성원 초대·공동 논문 등록 등 트랜잭션이 필요한 업무를 정리한다.

이 단계의 핵심 결과물은 확정된 데이터베이스 구조와 이를 설명할 설계 자료 및 SQL이다. 아직 사용자 화면을 갖춘 애플리케이션을 완성하는 단계는 아니다.

### 4차 애플리케이션 구현·검증

- 확정한 데이터베이스를 웹 애플리케이션에 연결하고 프로젝트 생성·수정, 구성원 관리, 공동 논문 추가·수정·삭제 기능을 구현한다.
- 논문 검색과 상세 정보, 직접 인용·피인용 논문 탐색, 판본 확인, 프로젝트별 논문 목록과 검토 상태·태그·메모 관리를 연결한다.
- 시연용 데이터로 주요 사용 흐름과 SQL 결과를 검증하고, 데이터 무결성 및 오류 상황을 점검한다. 실행 방법, ERD, 설계 변경 내용과 주요 SQL을 README 및 발표 자료에 정리한다.
- 구독 결제, 미공개 원고의 인용 시뮬레이션, BibTeX 내보내기는 이번 학기 구현 범위에서 제외한다.

### 추가적으로 확장 가능한 기능

이번 학기에는 제한된 논문 데이터 범위 안에서 인용 관계 탐색과 공동 문헌 조사 기능을 구현하는 데 집중한다. 다음 기능은 추가 데이터 검증과 권한·구독 관리, 서지정보 보완까지 필요하므로 이번 학기 구현 범위에서 제외한다.

- 여러 단계의 인용 관계를 그래프로 시각화하고 상세 조건으로 탐색하는 구독 기능
- 미공개 원고를 프로젝트 안에 초안으로 만들고, 기존 논문을 참고문헌 후보로 연결해 인용 관계를 시뮬레이션하는 기능
- 저장된 서지정보를 조합해 BibTeX를 생성·내보내고, 필수 항목 누락을 확인하는 기능
- 구독 등급, 결제 및 기능 접근 권한을 관리하는 기능

이 기능들은 현재의 논문·인용·프로젝트 데이터를 바탕으로 후속 확장할 수 있다. 이번 학기에는 기초 데이터 구조와 핵심 사용 흐름을 완성하고, 이후 단계적으로 기능을 보완한다면 연구자의 실제 문헌 조사와 논문 작성 과정에 활용할 수 있는 서비스 수준의 애플리케이션으로 발전할 것으로 기대한다. BibTeX는 원문을 논문마다 중복 저장하기보다 정규화된 서지정보에서 생성하며, 필요한 서지 항목은 해당 기능을 설계할 때 보완한다.
